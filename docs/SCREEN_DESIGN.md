### 2.5 SCR-001 개선안 v1.1 — 담당자 요청 반영 (2026-07-07) 🔷

목적은 **자사 인스타그램 계정 홍보용 콘텐츠 생성**이다. 아래 5개 요청을 SCR-001에 반영한다. 목업: 세션 아티팩트 `bg-scene-selector`.

| # | 요청 | 반영 방식 | 우선순위 |
|---|---|---|---|
| 1 | 인스타 홍보 목적 | 헤더 설명에 "인스타그램 발행 준비" 명시, 결과 SNS 카피/해시태그 유지 (SCR-004 포맷 다운로드로 연결) | 문구 |
| 2 | **배경 생성** | **상품 등록 카드에 "배경/씨 선택기" 신설 (아래 2.6). 확정 착수 항목** | **즉시 (본 개선의 착수 지점)** |
| 3 | 상품 이미지 그대로 유지 | 상품 원본 불변 게이트(SSIM) 유지 — 배경 변경 시에도 reference 제어로 상품 보존, 생성 후 재검수 | 기존 유지 |
| 4 | 모델 항상 일정 유지 | **구현됨** — 프론트가 첫 생성의 `model_id`를 세션 내 재사용(같은 Soul ID). 등록 카드에 "모델 고정됨" 뱃지 + "새 모델로" 리셋, 결과에 모델/Soul 상태 뱃지 | ✅ |
| 5 | 자연스러운 동작 연출 | **구현됨** — `camera_motion` 선택기(다가가기/멀어지기/회전/좌우/정적). ⚠ naturalness "점수"는 계산 로직이 없어 표시하지 않음(지어내지 않음). 자연스러움은 Agent2/4 프롬프트로 강제, 사용자는 카메라 워킹으로 연출 제어 | ✅ |

추가 반영(목업 기준, 기존 폼 대비):
- **품번** — 카테고리 기반 자동 채번(`JBL-{CAT}-{NNN}`), 수정 가능. 상단 노출.
- **상의/하의 구분** — 카테고리 1차 칩: 상의 TOP · 하의 BTM · 원피스 OPS · 아우터 OUT + 2차 세부 칩.
- **상품 이미지 프리뷰** — 업로드 즉시 3:4 썸네일 표시(교체/확대).
- **AI 이미지 분석 패널** — 색상 팔레트·소재·핏·디테일·스타일무드 + 신뢰도. 각 항목 담당자 수정 가능(ADR-012 직접 입력 원칙 유지, 자동은 초안 제안).

### 2.6 배경/씨 선택기 (요청 #2, 확정) 🔷

**결정 (2026-07-07 사용자 확정).**

- **동작 방식 = 씨/장소 프롬프트 주입.** 별도 배경 합성/아웃페인트가 아니라, 선택한 씨 설명을 화보 이미지 프롬프트에 주입한다. 모델·상품은 Soul ID·reference로 고정하고 배경만 자유 변수로 둔다. 기존 파이프라인(Agent2 프롬프트 조립 → Agent3 이미지 생성)에 프롬프트 절만 추가하면 되어 신규 인프라가 없다.
- **UI = 프리셋 칩 + 커스텀 텍스트.** 자주 쓰는 씨 프리셋 6종을 단일 선택 칩으로 제공하고, 필요 시 커스텀 텍스트로 직접 묘사한다(커스텀 입력 시 프리셋을 대체/보강).

프리셋 6종(초안): `studio_white` 스튜디오 화이트 · `city_street` 시티 스트리트 · `cafe` 카페·인테리어 · `nature` 자연·아웃도어 · `seasonal` 계절 무드 · `minimal_color` 미니멀 컬러.

배치: 상품 등록 카드 안, 상품명/타깃 아래 · 생성 시작 위. 옆에 "모델·상품 고정 · 배경만 변경" 상태 표시.

**불변 제약과의 관계 (중요).** 배경은 바꿔도 되는 유일한 자유 변수다. 배경을 바꿔 이미지를 재생성해도 상품 원본 불변(SSIM)·모델 동일성(Soul ID) 게이트는 그대로 적용되어, 게이트 미달 시 재생성 큐로 회송된다. 배경 변경이 상품/모델 보존을 우회하지 않는다.

#### 2.6.1 구성요소 ↔ API 매핑 (추가분)

| 구성요소 | 동작 | API |
|---|---|---|
| 배경 프리셋 칩 | 씨 6종 중 단일 선택 | 클라이언트 상태 |
| 배경 커스텀 텍스트 | 자유 프롬프트 입력(선택) | 클라이언트 상태 |
| 생성 시작(배경 반영) | `background` 파라미터를 파이프라인에 전달 | `POST /pipeline/run` (아래 필드 추가) |

`POST /pipeline/run` 요청 확장(안):

```json
{
  "product_id": "…",
  "model_id": "…(선택)",
  "background": { "preset": "city_street", "custom": "" }
}
```

- Agent2(프롬프트 조립, 규칙 기반 템플릿)가 `background`를 받아 씨 절을 프롬프트에 삽입한다. `custom`이 있으면 우선, 없으면 `preset` 매핑 문구를 사용. 둘 다 비면 기본값 `studio_white`.
- Agent3 이미지 생성의 상품 reference·Soul ID 주입은 불변. 배경 절만 달라진다.
- 백엔드 과제: `/pipeline/run` 스키마에 `background` 추가, 프리셋 키→프롬프트 문구 매핑 테이블(Agent2), 프롬프트에 씨 절 삽입. (TRD/개발계획서 정렬 필요.)

```
┌──────────────────────────────────────────────┐

│   [생성 화보 이미지]     │  ├ 자연스러움    0.85 ⚠ │
│    (나란히 비교)        │  └ 판정  manual_review │
│                       │                      │
│                       │  재생성 이력            │
```

### 3.2 기능 정의

| 기능 | 설명 | API(안) |
|---|---|---|
| 원본/생성물 비교 뷰 | 좌우 나란히, 확대 토글 | `GET /jobs/{job_id}` |
| QA 리포트 | SSIM·얼굴·naturalness 점수와 임계값 대비 pass/warn/fail 뱃지 | `result_refs.quality` |
| 재생성 이력 | `regeneration_attempts` 회차별 점수 타임라인 | `result_refs` |
| 승인 | Content status `draft → approved`, SCR-004로 이동 | `PATCH /contents/{id}` 신설 필요 |
| 재생성 | 프롬프트 보정 입력(선택) 후 재실행 | `POST /ai/image/generate` |
| 폐기 | job status `failed` 처리, 배포 제외 | `PATCH /jobs/{id}` 신설 필요 |

### 3.3 진입 조건

- 품질 게이트 판정이 `manual_review`(naturalness 0.8~0.9 구간, TRD §4) 또는 재생성 소진(`failed`)인 건
- SCR-001 결과 화면과 SCR-004 목록에서 진입

## 4. SCR-003 AI 모델 관리 🔷 계획 (트랙 B-5 연계)

### 4.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────────┐
│  AI 모델                        [+ 새 모델]     │
├──────────────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│ │[대표 이미지]│ │[대표 이미지]│ │  + 새 모델 │          │
│ │ MODEL_001 │ │ MODEL_002 │ │  만들기   │          │
│ │ Soul ✅   │ │ Soul STUB │ │          │          │
│ │ 20대 후반  │ │ 30대 초반  │ │          │          │
│ │ elegant  │ │ chic     │ │          │          │
│ └─────────┘ └─────────┘ └─────────┘          │
└──────────────────────────────────────────────┘

[+ 새 모델] 모달:
  헤어스타일 / 나이대 / 무드 / 패션스타일 입력
  (선택) 참조 이미지 업로드 → Soul 학습 (API 공개 시)
  → POST /ai/model/create
```

### 4.2 기능 정의

| 기능 | 설명 | API |
|---|---|---|
| 모델 카드 목록 | soul_reference_id 상태(실학습/STUB 뱃지), 속성 표시 | `GET /ai/models` 신설 필요 |
| 새 모델 생성 | 속성 입력 → 생성. Soul 학습 API 공개 전엔 STUB 뱃지 명시 (ADR-008) | `POST /ai/model/create` ✅ 기존 |
| 모델 선택 → 생성 | 카드에서 "이 모델로 생성" → SCR-001에 model_id 전달 | `POST /pipeline/run` (model_id) ✅ 기존 |

### 4.3 핵심 규칙

- 모든 생성에 동일 Soul ID 주입이 불변 제약이므로, 모델 삭제는 제공하지 않고 비활성화만 제공한다 (생성 이력 재현성 보존)

## 6. 공통 설계 규칙

### 6.1 상태별 공통 UI

| 상태 | 규칙 |
|---|---|
| 로딩 | 버튼 비활성 + 진행 문구 (스피너 도입 시 통일). 낙관적 업데이트 금지 (생성은 비용 발생 작업) |
| 오류 | 사용자 문구 + HTTP 상태코드 병기. 재시도 가능 상태 유지 |
| 빈 상태 | 목록 화면은 "아직 생성된 콘텐츠가 없습니다 + 생성하러 가기" CTA |
| 스텁 결과 | ⚠ 앰버 배너로 스텁임을 항상 명시 (실생성물 오인 방지, ADR-005) |

### 6.2 스타일

- Tailwind 기반, 시스템 다크모드 대응 (`dark:` 프리픽스) — 현 구현 유지
- 모바일 대응: 최대폭 `max-w-2xl` 중앙 정렬(현재). 비교 뷰(SCR-002)는 모바일에서 상하 스택으로 전환
- 언어: 한국어 단일 (PRD 범위)

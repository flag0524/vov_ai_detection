## 2. SCR-001 생성 메인 ✅ 구현

### 2.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────────┐
│  JBLANC AI Fashion 생성                        │  ← 헤더 (타이틀 + 설명)
│  상품 이미지를 업로드하면 화보 이미지·릴스        │
│  영상·SNS 카피를 자동 생성합니다.                │
├──────────────────────────────────────────────┤
│ ┌──────────────────────────────────────────┐ │
│ │ [파일 선택]  (image/* 단일 파일)            │ │  ← 업로드 카드
│ │ ┌───────────────┐ ┌───────────────┐      │ │
│ │ │ 상품명          │ │ 카테고리         │      │ │  ← 상품 정보 입력
│ │ │ 색상           │ │ 소재            │      │ │    (ADR-012, 2열)
│ │ │ 스타일          │ │ 타깃 고객        │      │ │
│ │ └───────────────┘ └───────────────┘      │ │
│ │ ┌──────────────┐                          │ │
│ │ │  생성 시작     │  (파일 없으면 비활성)      │ │
│ │ └──────────────┘                          │ │
│ │ (오류 시) ⛔ 업로드 실패 (400)               │ │
│ └──────────────────────────────────────────┘ │
├──────────────────────────────────────────────┤
│ (스텁 모드 시)                                 │
│ ⚠ Higgsfield 미연동 — 이미지/영상은 스텁 결과   │  ← 경고 배너
│                                              │
│ 화보 이미지                                    │  ← 결과 섹션 1
│   {image_url}                                │
│   상품 원본 유지율(SSIM): 0.92 — 통과           │
│                                              │
│ 릴스 영상                                      │  ← 결과 섹션 2
│   {video_url}                                │
│                                              │
│ SNS 카피                                      │  ← 결과 섹션 3
│   캡션 텍스트…                                 │
│   #제이블랑 #JBLANC #여성패션 …                 │
│   광고 카피 한 줄                               │
└──────────────────────────────────────────────┘
```

### 2.2 상태 정의 (Stage 상태 머신)

| 상태 | 트리거 | UI 표현 |
|---|---|---|
| `idle` | 초기 진입 | 버튼 "생성 시작", 파일 미선택 시 비활성 |
| `uploading` | 생성 시작 클릭 | 버튼 "업로드 중..." + 비활성 |
| `generating` | 업로드 성공 | 버튼 "생성 중..." + 비활성 |
| `done` | 파이프라인 응답 수신 | 결과 3섹션 렌더, 버튼 "생성 시작" 복귀 |
| `error` | 업로드/생성 실패 | 빨간 오류 문구 (`업로드 실패 (status)` 등), 재시도 가능 |

### 2.3 구성요소 ↔ API 매핑

| 구성요소 | 동작 | API |
|---|---|---|
| 파일 입력 | `image/*` 단일 선택 | — |
| 생성 시작 버튼 | 업로드 → 파이프라인 순차 호출 | `POST /product/upload` → `POST /pipeline/run` |
| 스텁 경고 배너 | 응답 `stubs.image \|\| stubs.video`가 true일 때 노출 | 응답 필드 |
| SSIM 표시 | `quality.ssim_score` + `overall_pass` ? "통과" : "재생성 필요" | 응답 필드 |
| 결과 3섹션 | image_url / video_url / sns{caption, hashtags, ad_copy} | 응답 필드 |

### 2.4 개선 예정 (현 구현의 한계)

- 이미지/영상이 URL 텍스트로만 표시됨 → 실생성 전환 시 `<img>`/`<video>` 미리보기로 교체 🔷
- 모델 선택 UI 없음 (매번 신규 모델 생성) → SCR-003 연동 모델 드롭다운 추가 🔷
- 동기 호출이라 생성 중 진행률 없음 → Redis 도입(ADR-007) 시 `GET /jobs/{id}` 폴링 진행바 🔷

## 3. SCR-002 검수·재생성 🔷 계획 (트랙 B-4)

### 3.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────────┐
│ ← 목록    검수 — job {job_id 앞 8자}            │
├───────────────────────┬──────────────────────┤
│                       │  QA 리포트             │
│   [원본 상품 이미지]     │  ├ SSIM        0.83 ✅ │
│                       │  ├ 얼굴 동일성   0.87 ✅ │
│   [생성 화보 이미지]     │  ├ 자연스러움    0.85 ⚠ │
│    (나란히 비교)        │  └ 판정  manual_review │
│                       │                      │
│                       │  재생성 이력            │
│                       │  1차: SSIM 0.74 ✗      │
│                       │  2차: SSIM 0.83 ✓      │
├───────────────────────┴──────────────────────┤
│  [ 승인 ]   [ 재생성 ]   [ 폐기 ]               │
│  재생성 시: 프롬프트 수정 텍스트박스 (선택)        │
└──────────────────────────────────────────────┘
```

### 3.2 기능 정의

| 기능 | 설명 | API(안) |
|---|---|---|
| 원본/생성물 비교 뷰 | 좌우 나란히, 확대 토글 | `GET /jobs/{job_id}` |
| QA 리포트 | SSIM·얼굴·naturalness 점수와 임계값 대비 pass/warn/fail 뱃지 | `result_refs.quality` |
| 재생성 이력 | `regeneration_attempts` 회차별 점수 타임라인 | `result_refs` |
| 승인 | Content status `draft → approved`, SCR-004로 이동 | `PATCH /contents/{id}` 신설 필요 |
| 재생성 | 프롬프트 보정 입력(선택) 후 재실행 | `POST /ai/image/generate` |
| 폐기 | job status `failed` 처리, 배포 제외 | `PATCH /jobs/{id}` 신설 필요 |

### 3.3 진입 조건

- 품질 게이트 판정이 `manual_review`(naturalness 0.8~0.9 구간, TRD §4) 또는 재생성 소진(`failed`)인 건
- SCR-001 결과 화면과 SCR-004 목록에서 진입

## 4. SCR-003 AI 모델 관리 🔷 계획 (트랙 B-5 연계)

### 4.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────────┐
│  AI 모델                        [+ 새 모델]     │
├──────────────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│ │[대표 이미지]│ │[대표 이미지]│ │  + 새 모델 │          │
│ │ MODEL_001 │ │ MODEL_002 │ │  만들기   │          │
│ │ Soul ✅   │ │ Soul STUB │ │          │          │
│ │ 20대 후반  │ │ 30대 초반  │ │          │          │
│ │ elegant  │ │ chic     │ │          │          │
│ └─────────┘ └─────────┘ └─────────┘          │
└──────────────────────────────────────────────┘

[+ 새 모델] 모달:
  헤어스타일 / 나이대 / 무드 / 패션스타일 입력
  (선택) 참조 이미지 업로드 → Soul 학습 (API 공개 시)
  → POST /ai/model/create
```

### 4.2 기능 정의

| 기능 | 설명 | API |
|---|---|---|
| 모델 카드 목록 | soul_reference_id 상태(실학습/STUB 뱃지), 속성 표시 | `GET /ai/models` 신설 필요 |
| 새 모델 생성 | 속성 입력 → 생성. Soul 학습 API 공개 전엔 STUB 뱃지 명시 (ADR-008) | `POST /ai/model/create` ✅ 기존 |
| 모델 선택 → 생성 | 카드에서 "이 모델로 생성" → SCR-001에 model_id 전달 | `POST /pipeline/run` (model_id) ✅ 기존 |

### 4.3 핵심 규칙

- 모든 생성에 동일 Soul ID 주입이 불변 제약이므로, 모델 삭제는 제공하지 않고 비활성화만 제공한다 (생성 이력 재현성 보존)

## 5. SCR-004 콘텐츠 라이브러리 🔷 계획 (트랙 B-3/B-4)

### 5.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────────┐
│  콘텐츠   [전체|승인됨|검수대기|실패] (필터 탭)    │
├──────────────────────────────────────────────┤
│ ┌────────────────────────────────────────┐   │
│ │ [썸네일] 상품명 · 2026-07-05              │   │
│ │  화보 ✅  릴스 ✅  카피 ✅   status: 승인됨  │   │
│ │  [Feed 1080x1350] [Reel 1080x1920]      │   │  ← 포맷별 다운로드
│ │  [Story 1080x1920] [캡션 복사]           │   │
│ └────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────┐   │
│ │ [썸네일] 상품명 · 2026-07-04              │   │
│ │  화보 ⚠ 검수대기 → [검수하러 가기]          │   │
│ └────────────────────────────────────────┘   │
└──────────────────────────────────────────────┘
```

### 5.2 기능 정의

| 기능 | 설명 | API |
|---|---|---|
| 콘텐츠 카드 목록 | 상품별 산출물 묶음(화보/릴스/카피) + 상태 | `GET /contents` 신설 필요 |
| 포맷별 다운로드 | Feed 1080x1350, Reel/Story 1080x1920 리사이즈 산출물 (B-3) | `GET /contents/{id}/export?format=` 신설 필요 |
| 캡션 복사 | caption + hashtags + ad_copy 클립보드 복사 (인스타 등록 준비) | 클라이언트 |
| 검수 진입 | 검수대기 건 → SCR-002 | 라우팅 |

### 5.3 범위 주의

- 인스타그램 자동 발행은 PRD 범위 외 — 이 화면의 종착은 "다운로드 + 캡션 복사"까지다 (등록 준비)

## 6. 공통 설계 규칙

### 6.1 상태별 공통 UI

| 상태 | 규칙 |
|---|---|
| 로딩 | 버튼 비활성 + 진행 문구 (스피너 도입 시 통일). 낙관적 업데이트 금지 (생성은 비용 발생 작업) |
| 오류 | 사용자 문구 + HTTP 상태코드 병기. 재시도 가능 상태 유지 |
| 빈 상태 | 목록 화면은 "아직 생성된 콘텐츠가 없습니다 + 생성하러 가기" CTA |
| 스텁 결과 | ⚠ 앰버 배너로 스텁임을 항상 명시 (실생성물 오인 방지, ADR-005) |

### 6.2 스타일

- Tailwind 기반, 시스템 다크모드 대응 (`dark:` 프리픽스) — 현 구현 유지
- 모바일 대응: 최대폭 `max-w-2xl` 중앙 정렬(현재). 비교 뷰(SCR-002)는 모바일에서 상하 스택으로 전환
- 언어: 한국어 단일 (PRD 범위)

### 6.3 API 신설 필요 목록 (백엔드 과제)

| API | 사용 화면 | 우선순위 |
|---|---|---|
| `GET /ai/models` | SCR-003 | 중 |
| `GET /contents` (목록) | SCR-004 | 중 |
| `PATCH /contents/{id}` (승인) | SCR-002 | 중 |
| `PATCH /jobs/{id}` (폐기) | SCR-002 | 하 |
| `GET /contents/{id}/export?format=` | SCR-004 | B-3와 함께 |

## 7. 구현 우선순위 (개발계획서 v2.0 연동)

1. **SCR-001 개선** — 실생성 전환 시 이미지/영상 미리보기 (트랙 A 완료 직후)
2. **SCR-002 검수·재생성** — 트랙 B-4. 실생성물에 품질 편차가 생기는 순간 필요해짐
3. **SCR-004 콘텐츠 라이브러리** — 트랙 B-3(인스타 포맷)과 함께
4. **SCR-003 모델 관리** — Soul 학습 API 공개(B-5) 시점에 맞춰
